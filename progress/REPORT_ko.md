## 1. 프로젝트 개요 (Project Description)

이 프로젝트는 영어 학습자가 문장을 읽는 녹음을 듣고, 문장을 이루는 **소리 하나하나(음소, phone)** 에 대해 **"맞게 발음했는지 / 틀리게 발음했는지"** 를 표시해 주는 AI 모델을 만드는 작업입니다. 이때 모델에는 원래 어떤 소리가 나와야 하는지(기대 음소, expected phone)도 함께 알려줍니다.

한국인 영어 학습자는 특정 발음을 반복해서 잘못 내는 경향이 있고, 정작 본인은 자기 발음이 틀렸다는 것을 잘 듣지 못합니다. 실제 L2-ARCTIC 데이터에서도 가장 흔한 실수는 `DH`를 `D`로 발음하는 경우(`the` → `de`)와 `Z`를 `S`로 발음하는 경우(`zoo` → `soo`)입니다. 하지만 시중의 대부분 영어 말하기 앱은 문장 전체에 대한 종합 점수 하나만 줄 뿐, **어느 소리를 고쳐야 하는지** 집어주지 못합니다.

모델 성능은 "틀린 발음(mispronounced)" 클래스를 기준으로 **정밀도(Precision)**, **재현율(Recall)**, **F1 점수**로 측정합니다. 평가에 사용하는 테스트 화자 6명은 학습 과정에서 한 번도 보지 못한 사람들입니다. 성공 기준은 다음과 같습니다.

- **1차 목표 (CNN vs 베이스라인)**: 직접 만든 CNN 모델의 F1 점수가 5개 랜덤 시드 모두에서 MFCC 로지스틱 회귀 베이스라인보다 높아야 합니다.
- **2차 목표 (사전학습 CNN vs 기본 CNN)**: 이후 추가할 사전학습(pre-training) CNN의 F1 점수가 처음부터 학습한(from scratch) CNN보다 높아야 합니다.

현재까지 데이터 전처리, 베이스라인 모델 구현 및 평가, 처음부터 학습한 CNN 5개 시드 실험과 오류 분석을 완료했습니다.

### 전체 파이프라인 구조

```
[구현 완료된 본선 경로]
음소 구간 (시작 시간, 끝 시간, 원래 나와야 할 소리)
  └─> 0.3초 log-mel 스펙트로그램 + 음소 위치 마스크 (2 x 64 x 30)
        └─> CNN 인코더 (합성곱 블록 4개 + 전역 평균 풀링)
              └─> [인코더 출력 + 원래 소리 임베딩(16차원)] 결합
                    └─> 완전연결층(FC) + 시그모이드 ─> 틀렸을 확률 P(mispron.) (예: DH = 0.91)

[앞으로 추가할 사전학습 경로 (계획)]
정답지 없는 녹음 17,379개 (테스트 화자 제외)
  └─> 같은 CNN 인코더로 "40개 음소 중 무슨 소리인가" 분류 학습
        └─> 학습된 가중치를 위 본선 CNN 인코더의 초기값으로 사용
```

## 2. 데이터 처리 (Data Processing)

데이터는 모국어가 6개(아랍어, 중국어, 힌디어, 한국어, 스페인어, 베트남어)인 외국인 영어 화자 24명의 녹음 데이터셋인 **L2-ARCTIC v5.0**을 사용합니다. 이 중 3,599개 문장 녹음에는 전문가가 소리마다 일일이 발음 오류를 표시한 수동 정답지(annotation)가 붙어 있습니다.

- **정답 라벨 정의**: 정답지 파일의 음소(phone) 층을 읽어, 다른 소리로 잘못 발음한 경우(대치, substitution)와 소리를 빼먹은 경우(삭제, deletion)를 모두 **"틀린 발음(1)"**으로, 제 소리를 낸 경우를 **"맞은 발음(0)"**으로 라벨링했습니다. 원래 없는 소리를 덧붙인 경우(첨가, addition)는 기준이 될 기대 음소가 없으므로 제외했습니다.
- **오디오 → 이미지 형태 변환**: 녹음을 16 kHz로 맞춘 뒤, 25 ms 창(window)과 10 ms 간격(hop)으로 **64-bin log-mel 스펙트로그램**(시간에 따른 주파수 에너지 그림)을 뽑았습니다.
- **0.3초 창과 마스크 채널**: 음소 하나는 길이가 매우 짧아(중간값 약 90 ms) 그 구간만 잘라서는 앞뒤 맥락 정보를 알기 어렵습니다. 그래서 음소를 중심으로 **앞뒤 포함 0.3초(30프레임) 창**을 잘라 첫 번째 채널로 넣고, 두 번째 채널에는 **"이 0.3초 중 어디부터 어디까지가 지금 판단할 그 음소인지"** 를 1과 0으로 표시한 이진 마스크(binary mask)를 넣었습니다. 최종 입력 크기는 `2 x 64 x 30`입니다.
- **화자 분리 (Speaker-disjoint split)**: 같은 사람 목소리가 학습과 시험에 동시에 들어가면 모델이 발음 오류가 아니라 사람 목소리 특징을 외울 수 있으므로, 화자 단위로 완전히 분리했습니다. 테스트 세트는 기존 L2-ARCTIC 선행 연구들이 사용하는 표준 6명(모국어별 1명)을 그대로 써서 다른 연구와 비교할 수 있게 했습니다.

| 구분 (화자 수) | 전체 음소 수 | 틀린 발음 수 | 오류 비율 |
|---|---:|---:|---:|
| 학습용 Train (12명) | 59,582 | 8,472 | 14.2% |
| 검증용 Validation (6명, 언어별 1명) | 29,783 | 4,906 | 16.5% |
| 테스트용 Test (6명, 언어별 1명) | 29,786 | 4,140 | 13.9% |

- **삭제(Deletion)된 음소 처리 확인**: 소리를 아예 빼먹은 음소는 실제 발화된 소리가 없는데 어떻게 구간을 자르는지 확인하기 위해, 전체 3,420개 삭제 음소 구간을 직접 조사했습니다. 조사 결과 길이가 0인 구간은 하나도 없었고, 주석자가 인접 소리 사이에 짧은 구간(중간값 40 ms)을 표시해 두었으며, 10 ms 한 프레임보다 짧은 구간은 13개뿐이었습니다. 코드에서도 마스크가 최소 1프레임은 항상 표시되도록 처리해 모든 삭제 음소가 유효한 입력을 만듭니다.
- **라벨 오타 정제**: 데이터 파싱 과정에서 `D_` 같은 정답지 오타가 발견되었습니다. 그대로 두면 6개의 가짜 음소 클래스가 추가될 뻔했으나, 이를 정리해 표준 **40개 음소** 목록으로 맞췄습니다.

## 3. 베이스라인 모델 (Baseline Model)

딥러닝 모델이 실제로 도움이 되는지 확인하기 위해 단순한 전통적 머신러닝 모델을 비교 기준으로 만들었습니다.

- 각 음소 구간에서 음성 특징인 **MFCC 13개와 1차·2차 미분값(총 39개)의 평균과 표준편차**를 구해 78개 숫자로 요약하고, 여기에 기대 음소를 나타내는 원-핫(one-hot) 벡터 40차원을 붙였습니다.
- 이 입력으로 클래스 가중치를 적용한 **로지스틱 회귀(Logistic Regression)** 를 학습했습니다.
- "틀림"으로 판정하는 기준값(threshold)은 오직 검증용(validation) 화자 데이터에서만 찾았습니다.
- 테스트 세트 결과 **F1 = 0.431**을 기록해, 아무 생각 없이 전부 "틀림"이라고 찍었을 때의 F1(0.244)보다 크게 높았습니다.

## 4. 주 모델: CNN 첫 실험 결과 (Primary Model: First Results)

주 모델은 제안서(Proposal)에서 설계한 CNN을 사전학습 없이 처음부터 학습한 버전입니다.

- **모델 구조 (총 260,577개 파라미터)**:
  1. `3x3` 합성곱 + 배치 정규화(BatchNorm) + ReLU + 최대 풀링(MaxPool)으로 이루어진 블록 4개 (채널 수: 32 → 64 → 128 → 128)
  2. 전역 평균 풀링(Global Average Pooling)으로 128차원 음향 벡터 추출
  3. 기대 음소 번호를 16차원 임베딩으로 변환한 뒤 위 128차원 벡터와 결합(144차원)
  4. 은닉층 128유닛(Dropout 0.3) + 시그모이드 출력층으로 틀렸을 확률 계산
- **학습 설정**:
  - 옵티마이저: Adam (학습률 $10^{-3}$, 배치 크기 256)
  - 손실 함수: 이진 교차 엔트로피(BCE). 전체 음소 중 약 7개 중 1개만 틀린 발음이므로, 소수 클래스인 "틀림"에 `(정상 수 / 틀림 수)`만큼 가중치를 더 주었습니다.
  - 조기 종료(Early Stopping): 검증 세트 F1이 3에포크 연속 오르지 않으면 학습을 멈추고 가장 좋았던 시점의 가중치를 복원했습니다.
  - 한 번 학습하는 데 노트북 GPU(Apple MPS) 기준 약 3분이 걸리며, 초기값 운에 따른 차이를 확인하기 위해 **5개 랜덤 시드(0~4)**로 반복 실험했습니다.

### 테스트 세트 성능 비교

| 모델 / 조건 | Precision (정밀도) | Recall (재현율) | F1 (종합) |
|---|---:|---:|---:|
| 전부 "틀림"으로 예측 | 0.139 | 1.000 | 0.244 |
| 베이스라인 (MFCC + 로지스틱 회귀) | 0.335 | 0.604 | 0.431 |
| **CNN (처음부터 학습, 5시드 평균 ± 표준편차)** | 0.383 ± 0.031 | 0.550 ± 0.042 | **0.450 ± 0.013** |
| 한국인 화자(YKWK)만: 베이스라인 | 0.362 | 0.635 | 0.461 |
| 한국인 화자(YKWK)만: CNN | 0.409 ± 0.032 | 0.586 ± 0.046 | 0.480 ± 0.019 |

### 결과 해석과 한계점

1. **성공 기준 통과, 하지만 격차는 작음**: 5개 시드 모두 전체 테스트 세트에서 베이스라인(0.431)을 이겼고, 한국인 화자(YKWK)에서는 5개 중 4개 시드가 베이스라인(0.461)을 넘겼습니다. 다만 평균 F1 차이는 `+0.019`로 큰 격차는 아닙니다.
2. **과적합(Overfitting) 신호**: 학습 손실(train loss)은 에포크가 지날수록 계속 떨어지지만, 검증 F1은 0.47~0.49 부근에서 멈춘 뒤 더 오르지 않습니다. Seed 4는 첫 에포크에서 최고 검증 점수를 찍고 4에포크 만에 조기 종료되었습니다(그럼에도 전체 테스트 F1은 0.439로 베이스라인을 넘겼습니다).
3. **정밀도 상승과 유성/무성 구분 개선**: CNN의 점수 향상은 주로 Precision이 `0.335`에서 `0.383`으로 오른 덕분입니다(대신 Recall은 `0.604`에서 `0.550`으로 소폭 하락). 오류 유형을 뜯어보면, CNN은 `D→T`(베이스라인 26% → CNN 48%)나 `P→B`(26% → 40%) 같은 유성/무성음 혼동 오류를 베이스라인보다 더 잘 잡아냈습니다(단, 각 모델이 검증 세트에서 찾은 서로 다른 임계값 기준이므로 단순 일대일 비교는 아닙니다).
4. **아직 해결하지 못한 약점 (`DH`, `TH`)**: `DH`와 `TH`는 원어민이 아닌 학습자가 매우 자주 틀리는 소리입니다(오류율 각각 57.5%, 44.1%). 베이스라인은 이 두 음소를 보면 거의 전부(재현율 0.998, 1.00) "틀림"으로 찍어 F1이 `0.730`, `0.613`에 도달하는데, CNN도 거의 같은 수준(`0.724`, `0.603`)에 머뭅니다. 즉 두 모델 모두 오디오를 제대로 듣기보다 **"이 음소는 원래 자주 틀린다"는 사전 정보에 기대어 판정**하고 있습니다.
5. **현재 실험의 한계**:
   - 표준편차(`±0.013`)는 학습 시드 변화에 따른 변동만 반영할 뿐, 테스트 화자 선정에 따른 변동은 반영하지 못합니다.
   - 한국인 테스트 화자가 YKWK 한 명뿐이므로, 한국인 대상 점수는 한국인 학습자 전반의 성적이라기보다 해당 화자 개인의 특성이 강하게 반영되었을 수 있습니다.
   - 테스트 시 사용한 음소 시작·끝 시간은 사람이 수동으로 표시한 경계이므로, 실제 발음 교정 서비스처럼 자동 정렬(forced alignment)만 있는 환경과는 다릅니다.

## 5. 향후 계획 (Next Steps, 12월 8일 최종 보고서까지)

1. **비지도/약지도 사전학습 구현**: 테스트 화자를 제외한 학습·검증 화자들의 정답지 없는 발화 **17,379개**와 자동 정렬(forced-alignment) 음소 경계를 이용해, CNN 인코더가 먼저 **40개 음소를 구분하는 분류기**로 학습하도록 만든 뒤 이를 오류 탐지 모델의 초기값으로 사용해 미세조정(fine-tuning)합니다.
2. **사전학습 유무 비교 실험 (Ablation)**: 사전학습을 적용한 CNN과 적용하지 않은 CNN을 각각 5개 시드로 학습해 같은 베이스라인과 비교합니다.
3. **자동 정렬 경계 기반 테스트**: 수동 정답지 시간 대신 코퍼스에 포함된 자동 정렬 시간 경계를 입력으로 주었을 때 성능이 얼마나 변하는지 측정합니다.
4. **과적합 완화**: 스펙트로그램에 시간/주파수 마스킹(SpecAugment 형태)을 적용하고 Dropout을 강화해 과적합을 줄입니다.
5. **추가 한국인 데이터 테스트 (시간 허용 시)**: 한국인 영어 학습자의 발음을 소규모로 직접 녹음해 추가 테스트 세트로 검증해 볼 계획입니다.
